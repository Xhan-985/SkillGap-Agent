# MARKET_RESEARCH —— AI 应用开发岗位市场研究（Phase 0）

> SkillGap Agent Phase 0 交付物之一
> 研究时间：2026-08-31 ｜ 地域范围：中国大陆为主 ｜ 数据观察期：2025-2026
> 结论一句话：**岗位市场活跃且技能证据充分，但公开渠道不存在系统化的"JD 技能频率"统计——自建数据集是本项目的核心研究价值，也是差异化根基。**

---

## 0. 研究方法与数据边界声明

- 本报告事实分两档标注：**[已核实]** = 来自实际打开的网页；**[线索]** = 来自搜索摘要或非权威来源，未独立核实。
- 不同招聘平台的统计口径（平台覆盖、岗位类目、时间窗）差异很大，增速数字不能线性外推。
- 培训机构口径的数据（如"需求增长 500%+""供需比 1:10"）一律标记为 [线索]，不作为决策依据。
- **最重要的数据边界**：公开渠道没有一份系统性的"AI 应用开发岗位 JD 技能出现频率"统计。目前唯一量化的公开数据是一篇 2026 年 5 月 CSDN/AtomGit 博客对 50+ 真实 JD（其中 23 个展开分析）的人工统计 [已核实，来源 5]。这是小样本非官方数据，只能作为方向线索。
- **推论**：SkillGap Agent 若要输出可信的技能频率，必须自建 JD 数据集（数百条级别）并公开统计口径。这既是工作量，也是护城河。

### 1.2 人才结构变化（对产品定位重要）

- 需求正从"训练模型的人"转向"让 AI 落地的人"：架构师新发职位 +76.74%、硬件工程师 +40.80%，均高于算法工程师的 +12.84% [3][已核实]

- **"AI 应用开发"已从"算法工程师"中独立成岗位类别**，岗位名称大量出现"Agent""智能体""全栈（LLM+Agent+MCP）"字样（见第 5 节）
- 博士年薪中位数 61.10 万 / 硕士 39.60 万 / 本科 28.50 万 [3][已核实]

### 2.3 对 SkillGap Agent 技能词表的直接启示

初版 Skill Taxonomy 应包含但不限于：`Python / Java / RAG / Agent(LangChain·LangGraph·AutoGen·CrewAI) / MCP / Dify / FastAPI / Docker / PostgreSQL / Redis / 向量数据库(pgvector·Milvus·Chroma·Qdrant) / Prompt Engineering / SFT·LoRA / vLLM / Evaluation / 多模态`。

## 3. 牛客面经：面试实际考察什么（需求侧最真实信号）

### 3.1 考察维度频率表（综合三篇牛客面经 [7][14][15]）

| 考察维度 | 频率 | 具体考点 |
|---|---|---|
| RAG 检索质量 | **极高** | chunk 切分策略、BM25+向量混合检索、rerank 模型选型、召回率低怎么办、评测指标（命中率/相关性/忠实度/幻觉率/badcase 集） |
| Agent 架构与 ReAct | **极高** | LLM 和 Agent 的区别、任务规划→记忆检索→工具选择→工具调用→观察→重规划/终止 |
| 上下文与记忆管理 | 高 | 窗口满了怎么办、摘要触发时机、短期/长期记忆设计 |
| Function Calling / MCP / 工具安全 | 高 | schema 设计、参数校验、失败重试、幂等、工具按需加载、Prompt 注入防护 |
| Workflow vs Agent 选型 | 高 | Prompt→RAG→微调→Workflow→Agent 的适用边界判断 |
| LLM 应用工程化 | 高 | 评测体系、降级、回滚、成本、首字延迟优化 |
| 项目深挖（"死亡追问"） | 高 | 模型选型依据、badcase、方案边界与局限 [7] |
| 后端基础 | 中 | 数据库、限流、缓存、K8s |
| 微调 | 中 | LoRA/QLoRA/SFT/RL |
| 向量库选型 | 中 | 选型标准、索引策略 |

### 3.2 对产品的启示

1. **面试官对"项目真实性"的拷问（"项目是你做的吗？"）恰好印证 SkillGap Agent 的"证据化能力画像"设计**——市场已被训练成要求证据，产品输出证据链是顺应需求。
2. RAG/Agent/工具安全是面试三大高频主题，与 JD 技能 Tier 1-3 完全吻合——**自建数据集的频率统计结果应能与面经信号互相验证**（这本身可以作为 Evaluation 的一部分：模型频率输出 vs 面经共识的一致性检查）。
3. "死亡追问"模式（为什么选这个模型、badcase 在哪、边界是什么）提示 SkillGap Agent 的推荐输出也必须能被追问：每个建议附"为什么"，可回溯到具体 JD。

## 6. 核心结论与对 SkillGap Agent 的启示

### 6.1 市场判断

1. **市场活跃，方向正确**：AI 应用开发/智能体开发岗位需求处于高位增长，且"应用层开发"独立成类——SkillGap Agent 选定的分析对象是一个真实、活跃、有独立身份的岗位族。
2. **技能假设大部分成立，但需自建数据验证**：Python/RAG/Agent 框架/Prompt 证据最强；MCP 是真实新兴需求（网易、金智维、金融科技 JD 均出现）；"哪些技能真的高频"这个问题的**权威答案不存在**——这正是 SkillGap Agent 的立足点。
3. **证据化能力是市场共识**：牛客面经的"死亡追问"文化证明，市场已经在要求"声明 vs 证明"的区分——SkillGap Agent 的 Evidence-based Skill Matching 直接回应这一真实痛点。
4. **可解释性是市场对 AI 产品的隐性要求**：面试追问"为什么选这个模型"与用户追问"为什么推荐我学 MCP"同构——产品的每个输出都应可追溯。

### 6.2 必须遵守的数据纪律（从研究直接导出）

- 所有频率统计输出必须标注：样本量 N、数据窗口、来源分布（手动导入/公开页面）、统计口径
- 样本量不足时明确输出"当前样本量不足以判断趋势"，禁止伪造趋势
- 禁止引用培训机构口径数据（500% 增长、1:10 供需比等 [线索]）
- 薪资与频率一样：只输出自建数据集的可复现统计
