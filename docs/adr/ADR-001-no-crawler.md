# ADR-001：为什么不爬招聘平台？

状态：**已接受（项目红线级，Phase 1 冻结）** ｜ 日期：2026-08-31 ｜ 前身：Phase 0 DESIGN_DECISIONS ADR-004

## Context

SkillGap Agent 的差异化根基是"真实、可追溯的中国就业市场 JD 数据"。但中国主要招聘平台（BOSS 直聘、牛客、拉勾、智联、猎聘）均无公开官方 API，平台条款普遍禁止自动化采集。原始规划文档（需求第三节）将"禁止爬虫"列为硬约束，明确禁止：绕过登录、绕过验证码、绕过反爬、模拟用户行为批量采集、未经许可抓取受限数据。

## Options

| 选项 | Pros | Cons |
|---|---|---|
| A. 平台爬虫（含"合规灰区"方案） | 数据规模大；能覆盖目标平台全部岗位 | 法律与平台条款风险（不正当竞争/数据权益纠纷先例多）；反爬对抗使项目建立在脆弱地基；与规划红线直接冲突；单开发者无力承担对抗成本 |
| B. 只用静态公开数据集（如 Open-Jobs 等） | 零采集成本 | 英文岗位为主，不覆盖中文垂直场景（本项目核心）；新鲜度与口径不可控 |
| C. 合法多通道（用户提交 + 公开页面人工摘录 + 公开 API） | 100% 合规可披露；数据永续（不依赖任何平台反爬态势）；来源可追溯（与数据透明性需求天然一致） | 规模天花板低（数百条级）；需要用户配合与人工收集成本（约 10 小时/200 条） |

## Decision

**选择 C：禁止任何形式的招聘平台爬虫（含灰区方案），中国岗位数据 = 用户主动粘贴 JD + 公司官方招聘页人工摘录 + 用户/社区 CSV/JSON 贡献；海外岗位数据 = 合法公开 API（见 ADR-002）。**

红线执行：任何触及爬虫的 PR 拒绝合并（代码评审 + 依赖检查）；不因"需要真实国内数据"重新讨论本决策。

## Consequences

- 正面：项目合法性不受平台政策变动影响；开源友好（数据来源全部可披露）；"用户主动提交 ≠ 平台抓取"的产品机制反而成为差异化叙事
- 负面：中国市场数据规模受限 → 必须以样本量守门（ADR-008）管理统计预期；人工收集有耐心成本

## Reversibility

撤销成本：**低**（多通道是增量设计，出现官方授权数据源时增量接入即可，前三级通道不变）。
复议触发条件：中国招聘平台开放官方 API 且许可统计聚合使用。
